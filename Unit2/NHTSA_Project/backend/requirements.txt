# NHTSA Project — Render backend dependencies
#
# Why this file is hand-curated (and not a `pip freeze` of the whole .venv311)
# ---------------------------------------------------------------------------
# The project's local virtualenv has dozens of macOS-only or notebook-only
# packages (mlx-audio, sounddevice, torch, whisper, jupyter, etc.) that have
# no business on a Linux web server and would either fail to install or bloat
# the build. Render's free tier already cold-starts slowly; trimming the
# install set keeps that responsive.
#
# Anything imported lazily (only inside a function body) by Voice_Tools,
# Audio_Capture, or generate_TTS_audio is intentionally NOT in this list —
# headless mode short-circuits those code paths before the import would run.

# --- Web server -------------------------------------------------------------
fastapi>=0.115,<1.0
uvicorn[standard]>=0.30,<1.0

# --- LangGraph + LangChain stack -------------------------------------------
# All three are imported at module load time by Graph.py / Nodes.py / config.py.
langgraph>=1.0,<2.0
langchain-core>=1.0,<2.0
langchain-openai>=1.0,<2.0

# --- Data layer -------------------------------------------------------------
# pandas reads NHTSA/complaints_cleaned.parquet at request time. pyarrow is
# pandas' parquet engine — pip won't pull it transitively, so it has to be
# named here explicitly or pd.read_parquet() will raise ImportError.
pandas>=2.0,<3.0
pyarrow>=15.0
numpy>=1.26,<3.0

# --- Misc utilities ---------------------------------------------------------
# python-dotenv: load_dotenv() is called from several modules. On Render the
# real env vars are already injected before Python starts, so load_dotenv is
# effectively a no-op there — but the import itself must still succeed.
python-dotenv>=1.0
# requests: used by Audio_Playback's Cartesia/Deepgram HTTP paths. Those paths
# are gated by is_audio_enabled(), which is False on the backend, so requests
# is *not* strictly required at runtime. It's kept here so the module imports
# cleanly even if a future code change moves a `requests` import to module top.
requests>=2.31

# --- Charting --------------------------------------------------------------
# matplotlib is INTENTIONALLY OMITTED here. It is the single biggest avoidable
# import in the LangGraph stack — ~150 MB resident — and Render's free tier
# is a 512 MB memory cap, so loading matplotlib at startup blew past the
# limit and crashed the instance.
#
# Chart_Tools.py wraps its matplotlib + Create_Charts imports in a try/except
# and exposes a `_CHART_BACKEND_READY` flag. When matplotlib is absent (this
# environment), each chart @tool short-circuits to a structured refusal that
# the LLM can read and adapt to. On the local CLI matplotlib is installed, so
# every chart still renders normally.
